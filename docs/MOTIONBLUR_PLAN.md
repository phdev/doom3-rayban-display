## What it is
A deterministic, tier-scaled fullscreen post-pass: reconstruct per-pixel screen-space velocity from the depth buffer + the camera's current/previous view-projection delta, then sample the composited frame along that velocity. Slots into the EndFrame post chain **after tonemap, before the GUI overlay**, reusing the proven substrate (`vs_main` fullscreen triangle, `currentRenderTex` BGRA8 scene copy, `makeBloom`/`fxPass` idiom, size-cache allocation, `g_cap*` cvar mirror, the LUT/det/false-green gate trinity). Default-OFF, `?motionblur`-gated, live-tunable; viewmodel excluded; cinematics suppressed. All edits in `neo/renderer` + `webgpu-port` + `scripts` — **zero SPINE/base-patch edits** (verified: `tr_render.cpp`/`draw_arb2.cpp`/`RenderSystem_init.cpp` are all renderer-owned).

## ⚠ Two honest findings that qualify "bloom-class"
1. **Depth is NOT sampleable on this backend.** `depthTexture` is `Depth24PlusStencil8`, `RenderAttachment`-only (renderer patch ~line 2204). Bloom never needed depth; motion blur does. So **P0 must add a sampleable depth resource via a small read-only-depth *resolve* pass** — and reading a depth aspect / depth-as-input is **backend-restricted on WebKit/Metal**, unproven until Mac Safari. **This is the real long pole and the genuine WebKit risk** — it's why motion blur isn't quite as free as bloom.
2. **`bloomBGL` can't be reused** (3 entries: 32 B UB + sampler + one Float color tex). Motion blur needs its own BGL (color tex + depth tex + a ~208 B matrix UB). Only the *idioms* are shared, not the layout.

## Kill-criterion (all four must hold)
1. **Operator correctness** — `__d3MotionBlurVelErr ≤ ~1 px` vs CPU reference (the reconstruction math is right, not merely plausible — catches a sign-flip/transpose/clip-z mismatch that the det arm would miss).
2. **Determinism** — `__d3WgpuDet` byte-IDENTICAL across a **moving-camera** sequence with blur on, and `__d3MotionBlurExecuted` advances inside the det encodes (false-green guard).
3. **Zero-velocity identity** — `r_motionBlurZeroVelocity 1` output byte-identical to the no-blur baseline.
4. **Phone budget** — Mac Safari WebKit.GPU RSS under 30 s sustained motion stays under the iter-30 threshold.

**Falsifiable:** the shipped mutation cvar `r_motionBlurScale 0` / `r_motionBlurZeroVelocity 1` must make the blur vanish (byte-identical to baseline) — if not, the pass is mis-gated → RED. A velocity-math regression drives `velErr` past tolerance → RED. A per-frame alloc/bandwidth regression drives RSS past ~1 GB → RED. (Same precedent as R0 `tonemapDrawCount` / R-GLTF `r_gltfSkinIdentity`.)

## Out of scope
Per-object velocity G-buffer (rejected for mobile); TAA/any temporal history (nondeterministic); HDR/RGBA16F (cut); subview/mirror blur (no prev-VP; main-view only); PBR & the rest of the program (motion blur is the item ahead of PBR); any `neo/game`/`neo/anim`/`neo/framework`/`rayban-base.patch` edit (`__d3InCinematic` consumed read-only via EM_ASM). **Target platforms = mobile (iOS Safari + Android Chrome) + desktop (Mac + PC) web browsers — NOT the Ray-Ban glasses (dropped 2026-06-23).** WebKit (iOS/Mac Safari) is the constrained stack; Mac Safari is the iOS-WebKit proxy for the RSS/NaN gates; Android Chrome + desktop Chrome are Dawn-class (covered by the Dawn gates).
